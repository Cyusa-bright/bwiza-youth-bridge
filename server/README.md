# BYB API

Express API for the existing React application. All routes are mounted at `/api/v1`. Requests that change state require the CSRF token returned by `GET /auth/csrf`; the React Axios client manages this automatically. Send/accept JSON. The browser session cookie is HTTP-only; responses contain safe user data only, never password hashes, session ids, or reset tokens.

## Development

Run `npm run dev:server` from the repository root (or `npm run dev` from `server/`). The API listens on `PORT`, defaulting to `5000`, so it can run alongside the Vite frontend on `5173`. Configure `FRONTEND_ORIGIN=http://localhost:5173` in the local server environment. The API root (`http://localhost:5000/`) and `/api/v1` return service information; `/health` and `/api/v1/health` check database readiness and return `503` if the database is unavailable. The frontend also proxies `/api` to the API by default. Set `VITE_API_PROXY_TARGET` to override that proxy target. Production deployments can set `PORT` and `FRONTEND_ORIGIN` for their deployment environment.

## Authentication

| Method and route | Request | Success |
|---|---|---|
| `GET /auth/csrf` | No body | `200 { "csrfToken": "..." }`; send it as `X-CSRF-Token` on state-changing requests. |
| `POST /auth/register` | `{ "name": "...", "email": "...", "password": "..." }` | `201 { "user": { "id", "name", "email", "avatarUrl", "emailVerified", "createdAt" }, "csrfToken": "..." }`; creates a member and signs them in. |
| `POST /auth/login` | `{ "email": "...", "password": "...", "rememberMe": false }` (`rememberMe` optional) | `200` with the safe user object and a rotated CSRF token; establishes a server-side session. |
| `POST /auth/logout` | No body | `204`; destroys the session and expires the cookie. |
| `GET /auth/me` | No body | `200 { "user": { ...safe user fields... } }`. |
| `PATCH /auth/profile` | `{ "name": "..." }` | `200 { "user": { ...safe user fields... } }`. |
| `POST /auth/change-password` | `{ "currentPassword": "...", "newPassword": "..." }` | `200 { "message": "Password updated.", "csrfToken": "..." }`; invalidates prior sessions. |
| `POST /auth/forgot-password` | `{ "email": "..." }` | `202` with a generic message that does not reveal whether the account exists. Requires configured mail delivery (`MAIL_HOST`, `MAIL_FROM`). |
| `POST /auth/reset-password` | `{ "token": "...", "newPassword": "..." }` | `200 { "message": "Password reset successfully. Please sign in." }`; reset tokens expire after 30 minutes and are single-use. |

Registration requires a 2–120 character name, valid email, and a password of at least 8 characters (maximum 72 UTF-8 bytes for bcrypt). Login, password changes, and password resets require at least 8 characters for the password; email is trimmed and lowercased before storage. Login and registration are rate-limited; password recovery has a stricter independent rate limit.

## Other API endpoints

| Method and route | Access | Request / success |
|---|---|---|
| `GET /api/v1/health` | Public | `200 { "status": "ok" }` when the database is reachable; `503` with `DATABASE_UNAVAILABLE` otherwise. |
| `GET /programs`, `GET /projects`, `GET /events` | Public | `200 { "items": [...] }`, published content only. |
| `GET /programs/:slug`, `GET /projects/:slug`, `GET /events/:slug` | Public | `200 { "item": {...} }`; `404` if unpublished or missing. |
| `GET /team` | Public | Published team-member profiles. |
| `GET /site-content` | Public | `200 { "items": [{ "key", "value", "updated_at" }] }`; website content stored as JSON values. |
| `GET /admin/access` | Signed-in user | `200 { "isAdmin": true/false }`; does not expose administrative data. |
| `GET /admin/programs`, `/admin/projects`, `/admin/events`, `/admin/team` | Admin | All records, including drafts and archived entries. |
| `GET /admin/:collection/:id` | Admin | Read one program, project, event, or team member by numeric id. |
| `POST /admin/:collection` | Admin | Create a content record; returns `201 { "item": {...} }`. |
| `PATCH /admin/:collection/:id` | Admin | Update a content record; returns the updated item. |
| `DELETE /admin/:collection/:id` | Admin | Delete a content record; returns `204`. |
| `GET /admin/site-content` | Admin | List editable website-content keys and JSON values. |
| `POST /admin/site-content` | Admin | `{ "key": "home", "value": { ... } }`; creates a website-content entry. |
| `GET /admin/site-content/:key`, `PATCH /admin/site-content/:key`, `DELETE /admin/site-content/:key` | Admin | Read, replace the JSON value, or delete one website-content entry. |
| `POST /admin/uploads` | Admin | Multipart form field `image`; JPEG, PNG, and WebP only; max 5 MB. Images are decoded and re-encoded before storage. Returns a generated `/api/v1/uploads/...` URL. |
| `GET /api/v1/uploads/:filename` | Public | Serves uploaded images with `nosniff`; uploaded names are generated by the server. |
| `POST /applications` | Signed-in user | `{ "programSlug": "..." }` or `{ "eventSlug": "...", "message": "..." }`; exactly one target. `201 { "id": "...", "status": "submitted" }`. |
| `GET /applications/my` | Signed-in user | `200 { "items": [...] }` for that user only. |
| `PATCH /applications/:id/withdraw` | Owning user | `200 { "id": "...", "status": "withdrawn" }` while submitted/reviewing. |
| `POST /contact-messages` | Public, rate-limited | `{ "name", "email", "subject", "message" }`; `201 { "id": "...", "message": "Your message has been received." }`. |
| `GET /admin/users?page=1&limit=25` | Admin | Paginated safe user data and assigned roles. |
| `PATCH /admin/users/:id/role` | Admin | `{ "role": "member" }` or `{ "role": "admin" }`; cannot remove the last administrator. |
| `GET /admin/contact-messages?page=1&limit=25` | Admin | Paginated contact messages. |

Content records accept `title` (or team `name`), optional `slug`, `category`, `image`, `status`, and a description (`summary` or `description`). Program detail lists may be sent as a `points` string array. Events also accept `starts_at`, optional `ends_at`, and `location`; team members accept `role`, `bio`, and `sort_order`. Status values are `draft`, `published`, or `archived` (events also support `cancelled`). Valid JPEG, PNG, and WebP uploads are decoded and re-encoded to strip metadata, then stored in `server/uploads`; back up that directory together with the database.

Errors use `{ "error": { "code": "...", "message": "..." } }`. Invalid input returns `400`, oversized uploads `413`, unauthenticated requests `401`, forbidden actions `403`, duplicate keys `409`, missing resources `404`, unavailable password recovery or database `503`, and rate limits `429`. Database/server failures return a generic `500` message; sensitive request data is not included in logs.

## Sessions and security

Sessions are opaque server-side records in MySQL. The `byb.sid` cookie is HTTP-only, `SameSite=Lax`, and `Secure` in production. Regular sessions expire after 12 hours; remembered sessions after 14 days. Login regenerates the session id; logout, password changes, and password resets invalidate session records. Mutating requests require a session-bound CSRF token. Configure one exact `FRONTEND_ORIGIN`; production configuration requires HTTPS origins, a non-example `SESSION_SECRET` of at least 32 characters, a non-empty `DB_PASSWORD`, and `DB_SSL=true` (certificate-verified TLS to MySQL). The API expects exactly one trusted proxy hop in production; configure the frontend host to serve its SPA fallback and HTTPS/HSTS.

Passwords are hashed with bcrypt. Password-reset tokens are cryptographically random, stored only as SHA-256 hashes, expire, and are single-use. Roles are not granted during public registration. To promote an existing registered account, use `npm run promote-admin -- user@example.org` from the repository root with the server environment configured.

## Migrations

Use MySQL 8.0.16+ or the MariaDB version bundled with XAMPP. Set DB connection values in the untracked `server/.env`, then run `npm run migrate` from the repository root. SQL migrations are ordered, additive, and tracked in `schema_migrations`; never edit an already-applied migration—add a new one instead. If the database contains the earlier BYB schema (`users.first_name`), the migration runner records that schema as a baseline and applies additive compatibility migrations without dropping existing tables or records. Migration 003 adds editable-content fields and the website-content table. Existing bcrypt hashes are retained; legacy plaintext passwords are moved into bcrypt hashes and removed from the old password column. Take a database and upload-directory backup before applying schema changes.

## Production deployment and recovery

Configure production variables in the hosting provider's secret manager, not in frontend build variables. Set `NODE_ENV=production`, `DB_PASSWORD`, `DB_SSL=true`, a randomly generated `SESSION_SECRET`, and exact HTTPS values for `FRONTEND_ORIGIN` and `FRONTEND_BASE_URL`. Set a Vite `VITE_API_BASE_URL` only when the API is not served from the frontend origin; never put secrets in `VITE_*` variables. Keep the frontend and API on the same site so the `SameSite=Lax` cookie works across their origins.

Terminate TLS at the trusted reverse proxy, expose only the proxy publicly, and ensure the request reaches Node through exactly one trusted proxy hop. Configure HSTS at the frontend host too. Run `npm ci` and `npm --prefix server ci`, back up before `npm run migrate`, start the API with `npm --prefix server start`, and serve the frontend's `dist/` with an SPA fallback. Mount `server/uploads/` on persistent storage; it is excluded from source control and will not survive an ephemeral deployment unless persisted.

Back up the MySQL database and `server/uploads/` on the same schedule. For a database dump, use a protected destination and let the MySQL client prompt for the password:

```sh
mysqldump --single-transaction --quick --triggers -h DB_HOST -u DB_USER -p DB_NAME > byb-backup.sql
```

For recovery, stop the API, restore with `mysql -h DB_HOST -u DB_USER -p DB_NAME < byb-backup.sql`, restore the matching uploads snapshot, restart the service, and verify database health and representative images. Encrypt and restrict backup access; routinely test recovery in a separate environment.
